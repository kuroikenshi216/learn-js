event loop
node is a single threaded runtime - meaning all requests are handled by a single thread (of the node process)
why? - the assumption seems to be that, most modern web apps are io bounded 
i.e they mostly wait for io dependent operations like waiting for a db, network packets, etc.
so instead of waiting idly blocking useful compute resources, the idea is to put it aside and work on other computational stuff (requests)
so this might not be ideal for cpu heavy tasks - altho ig you can move that stuff to separate worker threads?
so node allows us to scale to a large number of requests with a single thread since it concurrently processes everything efficiently

why not go for multiple threads?
threads/processes themselves take up useful resources which in turn can be used for something else
starting / stopping threads are expensive
you need to write threadsafe code (altho i dont think node by itself provides threadsafety)

so there are micro and macro tasks with their own queues
the event loop checks these queues for any tasks and executes them
after each macro task, micro q is checked and fully executed
