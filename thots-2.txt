Cleaned-up version of your notes

If I were turning your notes into a compact revision sheet:

TypeScript
──────────
• Superset of JavaScript.
• Adds static type checking and compile-time features.
• Valid JS is generally valid TS.
• TS-specific syntax must be compiled/removed before normal JS execution.
• TypeScript itself has no runtime; Node/V8 execute the resulting JS.
• tsc = TypeScript Compiler.
• tsconfig.json = compiler/project configuration.

Types
─────
• string
• number
• boolean
• bigint
• symbol
• null
• undefined
• arrays / objects are not primitives
• any = disables most type checking
• unknown = safer alternative when type is genuinely unknown

Annotations
───────────
let name: string = "Aakash";

Types can be inferred:
let name = "Aakash";

Objects
───────
interface User {
    name: string;
    age: number;
}

const user: User = {...};

Functions
─────────
function add(a: number, b: number): number {
    return a + b;
}

Unions
──────
string | number
"pending" | "completed"

Narrowing
─────────
if (typeof value === "string") {
    // value is string here
}

Interfaces
──────────
• Describe object contracts/shapes.
• Can extend.
• Can declaration-merge.

Type aliases
────────────
• Can describe object shapes, unions, tuples, etc.
• Cannot be redeclared/merged like interfaces.
• Can compose using intersections (&).

Generics
────────
function identity<T>(value: T): T

• Type parameter that preserves relationships between types.

Classes
───────
• public
• protected
• private
• readonly
• constructor
• no traditional destructor

Arrays
──────
string[]
number[]
Array<string>

Optional
────────
age?: number
→ optional / potentially undefined

Nullable
────────
age: number | null

Both
────
age: number | null | undefined

The three things I'd especially fix in your mental model are:

TS types disappear at runtime — they're primarily compile-time.
? means optional, not nullable.
interface vs type is more nuanced than "interface extends, type doesn't."

Everything else is mostly in place.
